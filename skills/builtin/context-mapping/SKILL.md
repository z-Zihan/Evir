# Context Mapping

1. Define the focal problem and boundary. A context map is not a complete architecture diagram.
2. Inventory actors, systems, data, artifacts, decisions, constraints, dependencies, terminology, and external interfaces.
3. Record relationships and direction: owns, supplies, consumes, approves, blocks, depends on, or conflicts with.
4. Mark every item as confirmed, inferred, disputed, or unknown, with a source where available.
5. Identify overloaded terms and mismatched mental models that could produce implementation or communication errors.
6. Keep sensitive identities and data minimized; use roles or redacted labels when details are unnecessary.

Return scope, glossary, actor/system map, dependency map, constraints, disputed assumptions, and questions to resolve.
