# Diagramming

1. Identify the audience, decision, diagram type, scope, and required level of detail.
2. List entities and relationships before drawing. Verify names, direction, boundaries, and cardinality from source material.
3. Choose the smallest useful notation: flow for sequence, state diagram for transitions, tree for hierarchy, map for relationships, or table when a diagram adds no value.
4. Use one visual grammar, meaningful labels, limited colors, and a clear reading direction. Avoid decorative nodes and crossing lines.
5. Distinguish current, proposed, external, optional, and failure paths. Include a legend only when the notation is not self-evident.
6. Validate that every arrow has a meaning and that the rendered artifact remains readable at its target size.

Return the diagram source in a format the current task can support, plus scope, assumptions, and unresolved relationships.
