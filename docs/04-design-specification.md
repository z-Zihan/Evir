# Evir 设计规范

## 1. 设计目标

Evir 应呈现为经过产品设计的专业工具，而不是通用 AI 模板拼装页。

关键词：克制、安静、清晰、可信、可审计、高信息密度但不拥挤。

避免：

- 大面积渐变、霓虹光、玻璃拟态堆叠。
- 到处使用紫色、机器人插画和“AI 星光”图标。
- 每个区域都做成圆角卡片。
- 过度胶囊按钮、巨大欢迎语、无意义动效。
- 相同权重的边框、阴影和强调色。
- 页面中心长期占据营销式空状态。

## 2. UI 技术方案

采用 shadcn/ui 的源码持有模式，底层使用 Radix Primitives；它不是不可修改的黑盒组件库。组件必须根据 Evir Token 和交互进行二次设计，不直接保留默认 Demo 外观。

推荐：

- Radix：可访问的交互 Primitive。
- Tailwind：布局和 Token 映射。
- Lucide：统一线性图标。
- Sonner：未来通知能力的候选方案；当前 UI 未实现通知中心。
- cmdk：未来命令面板的候选方案；当前 UI 未实现命令面板。
- react-resizable-panels：桌面分栏。

## 3. 信息架构

Desktop 默认三段式，但不强制三栏同时常驻：

```text
Sidebar               Main Workspace            Context Panel
PROJECTS / CHATS       对话、计划、工具执行        文件、变更、审批、详情
```

- Desktop 侧栏分 PROJECTS（项目 + 嵌套 thread）与 CHATS（Standalone 会话）两区；工作目录来自 Project，不在输入区选择。
- Composer 在 Project Thread 内含 Plan/Goal 特殊模式、Permission 与 Model 紧凑控制区；默认 Project Task 不显示 Agent 选择器。Standalone Chat 只有 Model。

Web 使用两段式：Sidebar（CHATS）+ Chat。窄屏折叠 Sidebar，不显示不存在的 Desktop 工具入口。

## 4. Design Token

必须使用 CSS Variables 建立语义 Token：

```text
background / foreground
surface / surface-elevated
muted / muted-foreground
border / input / ring
primary / primary-foreground
success / warning / danger / info
code-background
sidebar-background
```

圆角等级：

- `sm`：输入、列表项
- `md`：弹窗、菜单
- `lg`：主要浮层

不允许所有元素统一使用超大圆角。

## 5. 字体与排版

- UI：系统字体栈，优先平台原生观感。
- 代码：等宽字体栈。
- 正文默认 14px-15px；行高 1.55-1.7。
- 标题只通过字号、字重和间距建立层级，避免装饰线堆叠。
- 长文本最大阅读宽度受控；Agent 日志区域可更宽。

## 6. 间距

使用 4px 基础网格。常用间距：4、8、12、16、20、24、32。

同一组件内部紧密，不同信息区块之间明确。禁止通过大量空白掩盖信息结构问题。

## 7. 主题

- `system`、`light`、`dark` 三种模式。
- 切换时不得闪白；在 React 挂载前设置根节点 class。
- 暗色不是纯黑翻转，保持表面层级和边界可读。
- 主题只改变视觉，不改变功能或信息结构。

## 8. 核心组件规范

### 消息

- 用户与助手不强制使用大气泡；优先内容流。
- 工具调用与普通回答视觉区分。
- 代码块包含语言、复制、折叠和横向滚动。
- 长消息支持目录或段落导航（后续）。

### 工具执行卡片

固定展示：工具名称、状态、耗时、关键参数摘要、结果摘要。危险工具显示风险级别；完整输入输出按需展开。

### 审批弹窗

必须回答：Agent 要做什么、在哪里做、为什么需要、可能影响、是否可撤销。按钮为“拒绝”“本次允许”，高风险操作不提供模糊的默认确认。

### 空状态

空状态给出 2-4 个真实可执行示例，不使用营销口号和机器人插画。

## 9. 多语言与响应式

- 按钮不得依赖固定文字宽度。
- 文本可增长 50% 不截断核心信息。
- 图标按钮必须有 tooltip 和 aria-label。
- Web 支持常见桌面和移动浏览器宽度。
- Desktop 优先 1100px 以上窗口，支持最小窗口和面板折叠。

## 10. 设计验收清单

- 亮色/暗色/系统主题均检查。
- 中文和英文均检查。
- 空态、加载、错误、禁用、焦点、悬浮状态齐全。
- 键盘可操作；焦点环可见。
- 不存在明显 shadcn 默认示例拼装感。
- 同类页面层级、间距、按钮和反馈一致。

## 11. VS Code 扩展界面

Evir 扩展服从 VS Code Workbench，而不是把 Desktop 页面缩进侧栏。颜色、字体、焦点环、输入框和按钮优先使用 `--vscode-*` 语义变量；图标优先 Codicon 或与 Codicon 一致的线性 SVG。

### 11.1 信息层级

侧栏从上到下固定为：

1. Ask / Agent 模式与 Provider 设置。
2. 可滚动的会话和 Agent Activity。
3. 数据去向、审批或错误等当前任务状态。
4. 固定在底部的输入与发送/停止。

空态只显示标题、短说明和 2 个可执行示例。Agent 运行后必须优先显示当前步骤、工具状态和验证，不让营销空态或历史长文本挤走审批。

### 11.2 状态与组件

- 配置对话框：协议、Base URL、模型、密钥、能力来源、测试、取消、保存；测试中禁用重复提交。
- 模式切换：使用 `aria-pressed`；Agent 不可用时保留可发现性并显示唯一、具体原因。
- 消息：角色文案全部本地化；代码/路径使用等宽字体，普通回答允许选择和复制。
- Agent Activity：步骤、工具名、风险、耗时、结果摘要、验证和失败恢复；完整参数按需展开。
- 审批：危险对象、工作区位置、影响和可撤销性必须在按钮前；首焦点放在安全的“拒绝”。
- Composer：`Ctrl/Cmd+Enter` 发送，运行中替换为停止；停止后保留部分输出并明确“已停止”。
- Diff/回滚：使用 VS Code 原生 Diff Editor 与通知，不在 Webview 复制一个简化编辑器。

### 11.3 视觉规则

- 支持 240px-600px 常见侧栏宽度；任何主按钮不得因英文增长而被压到不可读。
- 4px 基础网格，紧凑控件高度遵循 VS Code 平台密度，不强行使用移动端 44px 控件。
- 不自定义大面积品牌背景；Evir 的识别来自图标、清楚文案和一致状态，不覆盖用户主题。
- Light、Dark、High Contrast 至少各检查一次；不得仅在默认 Dark Modern 下验收。
- 设置对话框在窄侧栏应留出外边距，按钮可换行但必须保持“测试 / 取消 / 保存”的主次关系。

## 12. CLI 终端界面

CLI 的 UI 是字符、空白、流、颜色和退出码。默认输出必须在无颜色、窄终端、管道和 CI 中仍可理解。

### 12.1 输出通道

- stdout：模型正文、命令要求的最终值或用户显式请求的 JSON/JSONL。
- stderr：状态、Provider/工作区披露、审批、警告和错误。
- 正常输出不得混入 Spinner 控制字符；检测到非 TTY 或 `NO_COLOR` 时禁用颜色与动画。
- 所有命令支持 `--help`；错误必须包含问题、原因和下一条可执行命令，禁止直接把 Zod/堆栈作为默认用户界面。

### 12.2 信息层级

```text
Evir / command
Target: provider, model, workspace
Status: configuring, testing, streaming, waiting approval, verifying
Result: response or task summary
Next: retry, fix configuration, inspect diff, or rerun
```

审批固定展示工具、风险、作用域、参数安全摘要和影响，使用 `Allow once? [y/N]`，默认值必须为 No。非交互终端直接拒绝并返回稳定退出码。

### 12.3 文案与可访问性

- 人类输出支持 `zh-CN` 和 `en`，语言由显式参数、环境或系统 Locale 决定；机器输出不翻译字段名。
- 不只依赖红/绿颜色表达成功失败，必须同时提供文本和退出码。
- 进度行在屏幕阅读器或日志环境下退化为离散事件，不能不断覆写同一行。
- 路径、Provider Host 和可能外发的本地内容在执行前明确展示；密钥永不回显。
- Ctrl+C 第一次请求安全停止并返回 130；若子进程不能及时终止，显示仍在停止的对象和下一步。

## 13. 跨产品面一致性

- Evir Web、Desktop、VS Code 和 CLI 使用相同的模式（Ask/Plan/Goal/Agent）、安全、数据去向和完成状态术语。
- 宿主平台约定优先：Desktop 使用 Evir Token，VS Code 使用 Workbench Token，CLI 使用终端能力；不追求像素级同形。
- 同一风险操作在各产品面都必须提供相同事实：做什么、在哪里、为什么、影响、是否可撤销。
- 未实时验证的连接或能力不得显示为“已连接”“支持”；应标为“用户声明”“未验证”或“测试失败”。
- 评审基线和当前缺口见 `docs/reviews/vscode-cli-product-ui-review.md`。

## 14. 设置、帮助与高级能力的复杂度控制

主界面不得同时展示个性化、Skill、MCP、用量和通知入口。当前已实现能力统一进入设置；未来若实现命令面板，可提供快捷访问，但不得把未实现入口写成当前能力。设置采用左侧一级分类 + 右侧内容，分类不超过 12 个。

审批和错误必须使用清楚的动作语言，不使用营销文案。Usage 优先展示关键数字，不堆叠仪表盘。通知、应用内帮助与反馈仍属于未来能力；实现前不得出现占位入口或完成声明。

## 15. 最终简洁性原则

- 新用户主流程只需要“接入模型 → 输入任务 → 必要时授权 → 查看结果”。
- 主界面不得同时出现 Skill、MCP、Memory、Usage、日志和 Provider 高级参数。
- 复杂任务进度以一条紧凑状态区和可展开时间线表达，不为每个内部模块创建常驻面板。
- 模型切换器默认展示当前模型和搜索；能力差异、费用和上下文问题只在切换时按需提示。
- 上下文压缩应在后台安全检查点完成，只在失败、需要用户决策或发生明显历史折叠时提示。
- 日志页属于设置/开发者诊断，不进入会话侧栏。
- 同一动作尽量只有一个主按钮；危险动作使用明确文本而非复杂多步骤向导。

## 16. 阶段 S 视觉基线

- Web 不渲染 Desktop 模式、项目或 MCP；Desktop 侧栏为 PROJECTS/CHATS，模式与权限控件在 Project Thread 的 Composer 内。
- 工作目录来自 Sidebar 的 Project（含 Folder not found 徽标与重绑引导），不作为页面主 CTA。
- 设置对话框使用分组导航，并满足首焦点、焦点循环、Escape 与关闭后焦点恢复。
- 自动截图矩阵覆盖 Web/Desktop、zh-CN/en、Light/Dark、1600×1000 至 390×844；核心视觉基准位于 `e2e/snapshots/`。
- Agent Activity 的总体状态和当前步骤优先于历史工具详情；完成项弱化，原始参数按需展开。
- 嵌套浮层优先处理 Escape，父对话框不得同时关闭；可滚动内容区必须可聚焦并有名称。
- 选中状态必须通过 `aria-pressed`、`aria-selected` 等语义表达，不能只依赖颜色。
- Agent 的取消/中断状态不得显示为完成；Provider/MCP 未完成实时验证时不得使用“已连接”。

## 17. 任务工作台

- 复杂 Desktop Agent 任务在聊天流内显示紧凑工作台，不新增常驻 Agent 管理页。
- 状态栏优先展示当前阶段和当前节点，并提供检查点暂停、恢复和停止；停止后的节点不得显示完成。
- 澄清卡最多展示 3 个关键问题、建议答案、假设和数据去向；出现时焦点进入首个问题。
- 时间线展示依赖、并行组、验证和弱化的完成项；只读关系图按需展开，原始工具输出不进入全局 React 状态。
- 子 Agent 只展示任务、状态和结果摘要，不展示私有推理。窄窗口使用单列，操作可换行且保持键盘、焦点环和屏幕阅读器名称。
