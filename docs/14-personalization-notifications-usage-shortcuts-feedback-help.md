# Evir 个性化、通知、用量、快捷键、反馈与帮助规范

## 1. 目标与产品原则

这些能力用于提高可控性和效率，但不得让 Evir 的主流程变复杂。默认聊天页仍只突出：选择模型、选择模式、输入、发送/停止。个性化、用量、快捷键、帮助和反馈统一收纳到设置页；只有与当前任务直接相关的状态才在主界面出现。

## 2. 设置页信息架构

```text
设置
├── 通用：语言、主题、启动与更新
├── 模型供应商：Provider、协议、模型、官网/控制台/文档
├── 个性化：用户信息、角色、表达风格、自定义指令
├── Agent：默认模式、权限、网络、记忆
├── Skill
├── MCP（Desktop）
├── 通知
├── 快捷键
├── 用量统计
├── 数据与隐私
├── 帮助
├── 提交反馈
└── 关于 Evir
```

高级选项默认折叠，设置项必须可搜索。

## 3. 个性化与自定义指令

### 3.1 简单模式

普通用户通过表单配置：称呼、常用语言、回答详细程度、表达风格、技术偏好、希望 Evir 始终遵守的工作习惯。支持总开关、预览最终效果、恢复默认和仅当前会话覆盖。

### 3.2 高级 Markdown 模式

允许用户编辑：

- `USER.md`：用户背景、偏好和长期上下文。
- `PERSONA.md`：Evir 扮演的角色、语气、专业领域和表达风格。
- `INSTRUCTIONS.md`：用户自定义工作指令。
- `SOUL.md`：可选高级层，用于长期价值取向、交流原则和行为风格；不等同于系统安全 Prompt。

支持导入、导出、版本历史、启用/禁用和作用域：全局、工作区、会话。

### 3.3 不可编辑边界

以下内容不可由用户、Skill、MCP、网页或项目文件编辑或覆盖：

- Evir 核心运行规则。
- 安全与 Prompt Injection 防护。
- 权限和网络外发策略。
- 工具执行、审批和审计规则。
- 系统数据保护与隐私边界。

内部可表示为 `CORE.md`、`SECURITY.md`、`PERMISSIONS.md`、`TOOL_POLICY.md`，但产品无需暴露原始文本。用户可查看原则说明，不能修改规则。用户可编辑 Markdown 始终是低优先级上下文，不能通过“忽略之前规则”等文字提权。

### 3.4 合并顺序

```text
Evir Core
> Security / Permission / Runtime Mode
> 用户自定义指令
> Persona / Soul
> Active Skills
> Workspace Context
> Conversation Override
> 外部不可信内容
```

个性化必须支持“一键临时关闭”，隐私会话是否加载个性化由用户设置决定。

## 4. 系统通知

### 4.1 平台能力

- Desktop：使用 Tauri Notification Plugin 调用 macOS/Windows 系统通知。
- Web：在用户明确授权后使用浏览器 Notification API；不支持时仅显示应用内提示。

### 4.2 默认行为

系统通知默认关闭，不在首次启动时弹出系统权限请求。用户在设置页开启后才申请权限。默认只在 Evir 不处于前台时通知：

- 长任务完成。
- 任务等待用户审批。
- 任务失败。
- 可选的软件更新提醒。

短聊天回复默认不发系统通知。通知正文默认不包含用户 Prompt、文件名、代码或敏感内容；“显示内容预览”必须由用户主动开启。设置页可关闭全部通知或按事件关闭，遵守系统勿扰模式。

## 5. Token 与用量统计

### 5.1 记录内容

每次模型请求记录：Provider、协议、模型、时间、会话/任务、输入、输出、缓存读取、缓存写入、推理和工具 Token（供应商提供时）、总 Token、错误与重试次数。

### 5.2 准确性

- 优先使用 Provider 响应返回的准确 usage。
- Provider 不返回时，可以使用对应 tokenizer 估算，并明确标记“估算”。
- 无可靠 tokenizer 时显示“不可用”，不得伪造精确数据。
- 流式接口通常在结束事件返回 usage，界面应在结束后补齐。

### 5.3 统计页面

支持今日、7 天、30 天、自定义时间；按 Provider、模型、会话和 Agent Run 查看；展示请求数、Token、失败率、平均首 Token 时间、平均响应时长和可选费用估算。

费用仅在价格元数据可靠且带版本时显示，并明确标记为估算。用户可自定义价格或关闭费用显示。数据默认仅本地保存，可导出 CSV/JSON、清空或关闭持久化。隐私会话只显示当前会话用量，不写入长期统计。

## 6. 快捷键基础设施

### 6.1 应用内快捷键

默认提供：

- `Cmd/Ctrl + K`：命令面板。
- `Cmd/Ctrl + N`：新建会话。
- `Cmd/Ctrl + ,`：打开设置。
- `Cmd/Ctrl + B`：显示/隐藏侧边栏。
- `Cmd/Ctrl + Shift + O`：打开工作区（Desktop）。
- `Cmd/Ctrl + Shift + F`：搜索会话。
- `Cmd/Ctrl + Enter`：发送消息。
- `Esc`：停止当前生成/关闭最上层弹窗；有歧义时先关闭弹窗，不静默停止危险任务。
- `Cmd/Ctrl + /`：快捷键帮助。

输入框默认 Enter 发送、Shift+Enter 换行，并允许用户改为 Enter 换行、Cmd/Ctrl+Enter 发送。

### 6.2 自定义与冲突

快捷键设置页支持搜索、录制、冲突检查、恢复默认和按平台显示。浏览器保留快捷键必须提示可能无法覆盖。Desktop 全局快捷键属于高级功能，默认关闭，只有用户明确开启后才注册；退出或禁用时必须注销。

## 7. Provider 官方链接

每个内置 Provider Preset 应包含：官网、控制台、开发文档和可选状态页。设置页以外部链接展示，并明确这些链接不会改变 API Endpoint。链接必须由 Evir 预置或用户明确填写，禁止使用模型生成的未知链接。打开外链前使用系统默认浏览器。

## 8. 提交反馈

设置页提供“提交反馈”：

1. 选择 Bug、功能建议或其他。
2. 在 Evir 内填写标题和描述。
3. 可选生成脱敏诊断摘要，用户必须预览和勾选后才能加入。
4. 打开 `https://github.com/z-Zihan/Evir/issues/new/choose` 或带查询参数的 Issue 页面。
5. 用户在浏览器登录 GitHub 并最终提交。

Evir 不需要 GitHub Token，也不在后台直接创建 Issue。不得自动上传 API Key、完整会话、文件正文、环境变量、SSH 信息或未预览的日志。仓库内提供 Bug 和 Feature Issue 模板。

## 9. 帮助与使用说明

设置页提供可搜索的内置帮助中心，中英文随应用语言切换，并可离线访问。至少包含：

- 快速开始。
- 添加模型供应商。
- Ask / Plan / Agent 区别。
- 个性化与自定义指令。
- Skill 使用、导入和创建。
- MCP 配置与排错（Desktop）。
- 权限、网络与数据外发。
- 快捷键。
- Token 与用量统计。
- 数据、备份和隐私会话。
- 常见问题与故障排查。
- 提交反馈与诊断包。

帮助页不应只是文档列表：错误提示、空状态和设置项可以链接到对应主题。在线文档是可选补充，离线帮助必须覆盖首次使用闭环。

## 10. 数据与性能

- 个性化 Markdown 保存为小型本地文件或结构化配置，必须有版本和原子写入。
- 通知设置、快捷键和帮助阅读状态属于轻量设置，不进入大型 React Store。
- Usage 记录批量写入，禁止每个流式 Token 写数据库。
- Token 图表和历史记录按需加载，默认不进入首屏 Bundle。
- 快捷键监听统一注册，不允许组件各自添加全局监听造成泄漏。
- 设置页路由按模块懒加载。

## 11. 验收标准

- 用户能在 3 步内完成简单个性化，并能一键关闭。
- 用户自定义内容无法修改安全与权限规则。
- 未开启通知时，应用不请求系统通知权限。
- 统计页面能区分准确、估算和不可用 usage。
- 快捷键可发现、可修改、可恢复且不存在静默冲突。
- Provider 页面可打开官网、控制台和官方文档。
- 反馈流程不要求 Evir 后端或 GitHub Token。
- 新用户可仅依赖内置帮助完成 Provider 配置和第一次对话。
