# Evir Agent 安全与质量规范

## 1. 信任边界

以下内容均视为不可信数据，而不是高优先级指令：网页、仓库文件、文档、终端输出、MCP 返回值、插件和 Skill 内容。

只有产品系统规则、用户明确输入和经过授权的策略可以改变权限。

## 2. 风险等级

- L0：纯推理、读取非敏感会话数据。
- L1：读取授权工作区、只读 Git、普通搜索。
- L2：工作区内创建/修改文件、构建和测试。
- L3：删除、安装依赖、网络外发、Git 写操作。
- L4：发布、支付、凭据、系统目录、sudo、不可逆操作。

L3/L4 默认逐次审批；L4 可直接禁用。

## 3. 路径安全

- 所有路径 canonicalize。
- 防止 `../`、符号链接和挂载点逃逸。
- 明确授权根目录。
- 敏感目录默认 deny：`.ssh`、系统凭据目录、浏览器配置等。

## 4. 命令安全

- 优先 program + args，不经过 shell。
- 限制 cwd、环境变量、执行时间和输出体积。
- 支持停止整个进程树。
- 危险命令展示原始预览，不只展示模型解释。

## 5. 质量验证

任务完成至少满足一类外部证据：

- 文件/数据库状态符合预期。
- 命令退出码为 0。
- 测试、Lint 或构建通过。
- 页面或接口探测成功。
- 用户明确确认结果。

## 6. 回滚

- 写入前建立文件快照或 patch。
- 一个 Agent Run 对应一组可撤销变更。
- Git 仓库不得默认 reset 用户现有未提交修改。
- 非 Git 目录使用应用级快照。

## 7. 日志与隐私

- 日志默认本地。
- 密钥、Authorization、Cookie、Token 自动遮盖。
- 工具完整输出可归档，但进入模型前需最小化。
- 用户可清除单次任务、会话或全部数据。

## 8. 宿主产品面边界

- VS Code Agent 还必须满足 Workspace Trust、本地 `file` Workspace、Extension Host 路径校验；Webview 不能持有工具执行能力。
- CLI Agent 还必须满足真实绝对工作区和交互式审批；非 TTY 默认拒绝写入和命令。
- VS Code/CLI 的用户声明 Tool Calling 只属于 `user-override`，未经探测不得标为“已验证”。
- 四个产品面的审批都展示同一组事实：工具、风险、作用域、原始参数安全摘要、影响和可撤销性。
- Agent 完成状态来自工具/验证证据，不来自 Webview、终端 Presenter 或模型结束文本。

## 9. 产品面验证

- VS Code：真实 Extension Host 中验证未信任/Remote Workspace 拒绝、路径逃逸、逐次审批、Stop、Diff 与回滚冲突。
- CLI：验证 TTY/非 TTY、stdout/stderr、退出码、SIGINT、路径/符号链接、命令参数和输出上限。
- 构建 `.vsix` 或 npm tarball 只证明可打包，不证明上述安全闭环通过。
