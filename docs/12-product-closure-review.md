# Evir 产品闭环审查（V6）

> **Historical（2026-08-06 决策记录）**：本文记录阶段 S 前后的产品闭环方法论与决策史，保留作历史依据。当前产品模型（Sidebar Projects/Chats、Composer Agent/Plan/Goal、Permission Profiles）以 `docs/project-chat-agent-redesign.md` 与 `docs/agent/Evir-project-memory.md` 为准；本文涉及模式、工作区与 MCP 状态的段落是当时的快照。

## 1. 审查目标

本审查从产品可用性而非单纯功能数量出发，检查用户从首次打开、接入模型、完成对话或任务，到数据管理、故障恢复和长期使用是否形成完整闭环。

结论：Evir 的主体方向成立，但 V3 在运行模式边界、Provider 接入失败处理、模型能力判定、Web/Desktop Skill 边界和系统权限获取上存在不闭环或容易误解的地方。V4 已将这些问题纳入 PRD、技术规范与开发计划。

## 2. 已发现并修正的闭环问题

### 2.1 Ask / Plan / Agent 边界不闭环

原问题：Plan 被描述为完全不执行工具，但没有只读检查就无法根据真实项目制定可靠计划。

V4 决策：

- Ask：不自主访问本地资源，只处理用户输入和用户主动添加的附件。
- Plan：允许在用户明确授权的工作区内调用只读工具，例如列目录、读文件、搜索、Git status/diff；禁止写文件、安装依赖和执行会改变状态的命令。
- Agent：允许按权限策略执行写入和命令。

模式切换后，Tool Registry 必须重新计算可用工具，不能只通过提示词约束。

### 2.2 Web Provider 直连失败后没有下一步

原问题：Web 无后端并依赖浏览器直连，但 CORS、认证方式和浏览器安全策略可能导致某些 Provider 无法使用。

V4 决策：

1. 添加 Provider 时先进行无副作用的连接测试。
2. 区分认证失败、CORS、网络、模型不存在和协议不兼容。
3. CORS 失败时明确显示：该端点不能在 Evir Web 直接使用。
4. 提供两个合法下一步：改用 Evir Desktop；改用支持浏览器直连的端点。
5. Evir 不偷偷使用公共代理，也不把用户密钥发往 Evir 服务。

### 2.3 Provider 与模型能力被混为一体

原问题：同一 Provider 下不同模型对工具、图片和结构化输出的支持可能不同，不能用 Provider 级布尔值决定 Agent 是否可用。

V4 决策：

- Provider Preset 只描述厂商、端点、区域和认证。
- Protocol Adapter 描述请求/响应协议。
- Model Profile 描述具体模型能力。
- 能力来源记录为 preset、provider metadata、probe 或 user override。
- Agent 模式必须基于当前模型的能力判定。

### 2.4 能力检测可能产生费用或副作用

原问题：为了检测 Tool Calling、图片和结构化输出，直接发测试请求会产生费用，也可能被模型执行服务端工具。

V4 决策：

- 第一层读取预置元数据和模型列表。
- 第二层只做最小文本流式探测。
- Tool Calling、图片、结构化输出探测需要用户确认“执行能力测试，可能产生少量费用”。
- 能力测试不得启用服务端搜索、代码执行或远程 MCP。
- 用户可手动覆盖，但 UI 必须显示“未经验证”。

### 2.5 模型列表获取失败后无退路

V4 决策：

- 支持模型列表接口的 Provider 自动加载。
- 加载失败时允许手动输入模型 ID。
- Provider 的模型列表缓存必须有更新时间和刷新操作。
- 区域、账号和 API Key 变化后清除旧模型缓存。

### 2.6 Web 与 Desktop 的 Skill 边界不清晰

V4 决策：

- Evir Web 支持“指令型 Skill”：只能包含提示词、流程、输出规范和对上传内容的处理规则。
- Web Skill 不允许声明 filesystem、terminal、local MCP、script 等能力。
- Evir Desktop 支持完整 Skill，包括本地能力依赖和 MCP 依赖。
- 从 Desktop 导出的完整 Skill 导入 Web 时，必须以“能力不兼容”阻止安装或降级为只读预览，不能静默忽略依赖。

### 2.7 MCP 添加成功不等于可用

V4 决策：MCP 闭环包含添加、连接、能力发现、逐项授权、测试调用、运行时使用、断线重连、日志、停止和删除。新增 Server 默认禁用。删除时终止子进程并清理非敏感缓存；密钥引用由安全存储单独管理。

### 2.8 Skill 创建完成不等于可用

V4 决策：Skill 创建闭环必须包括目标、触发条件、反例、流程、能力依赖、输出格式、预览、验证、测试、安装和版本记录。未通过基础结构检查的 Skill 只能保存草稿，不能启用。

### 2.9 系统权限首次启动过度索取

V4 决策：Desktop 采用渐进授权。

- 首次启动只配置模型，不申请文件、辅助功能或屏幕录制权限。
- 用户首次选择工作区时请求目录权限。
- 首次启用 Computer Use 时分别解释并申请 Accessibility、屏幕录制等权限。
- 用户拒绝后保留其他功能，并提供系统设置指引。

### 2.10 Agent “完成”缺少产品级确认

V4 决策：任务完成页必须显示：

- 目标和实际完成状态。
- 变更文件和 Artifact。
- 执行过的命令与审批。
- 验证证据。
- 未完成项和风险。
- 撤销入口。

模型文本不能独立决定任务完成，必须由 Run Manager 和验证器确认。

### 2.11 停止、退出和崩溃后的状态不明确

V4 决策：

- 停止生成：取消当前模型流，不自动取消已完成工具。
- 停止任务：取消模型流并终止当前可终止工具和子进程。
- 退出应用：有运行任务时提示暂停并退出、停止并退出或返回。
- 崩溃恢复：恢复计划和状态，但不自动重放写操作或危险命令。

### 2.12 自动降级和 Provider 切换可能泄露数据

V4 决策：默认不自动将同一请求发送到另一 Provider。模型失败时只提供重试、切换模型和复制错误。跨 Provider 自动回退属于未来可选功能，必须显式启用并说明数据将发送给哪些服务。

### 2.13 Provider 内置工具与 Evir 工具容易混淆

V4 决策：UI 和审计必须区分：

- Evir Local Tool：在用户设备执行。
- MCP Tool：由本地或远程 MCP Server 执行。
- Provider Tool：由模型厂商服务端执行，例如搜索、代码解释器。

Provider Tool 默认关闭，启用时显示数据将发送并由厂商执行，受 Network Policy 控制。

### 2.14 推理内容处理不闭环

部分 Provider 在工具调用续轮时要求回传厂商特定的 reasoning/thinking 元数据。V4 要求 Adapter 将其作为 opaque provider state 保存并回传，但 UI 不展示模型私有思维链。可展示的仅是厂商明确提供的摘要或 Evir 生成的任务状态摘要。

### 2.15 无账号产品的数据迁移闭环

V4 保留本地优先，同时提供导出、导入、备份、迁移和删除。API Key 默认不导出。删除 Provider、会话、记忆、Skill 和 MCP 后必须清理对应本地数据和安全凭据引用。

### 2.16 费用透明闭环

对于能返回 usage 的 Provider，Evir 展示本轮和会话累计 Token；有可靠价格元数据时展示估算费用，并注明“估算”。未知价格不猜测。能力探测、重试和工具续轮也计入用量。

### 2.17 轻量目标与功能扩展冲突

V4 决策：浏览器自动化、文档解析、大型语法高亮和本地模型管理采用按需模块。Sidecar 不随应用启动。Skill 只加载索引，命中后再加载正文。MCP 只有在启用并被任务需要时启动。

## 3. 完整用户旅程

### 3.1 Web 首次成功对话

打开 Web → 选择语言/主题 → 添加 Provider → 选择协议和区域 → 输入 Key → 拉取或填写模型 → 连接与流式测试 → 显示能力 → 创建会话 → 流式回答 → 保存本地 → 导出或删除。

失败分支均应有明确下一步，尤其是 CORS、Key 错误、模型错误和协议错误。

### 3.2 Desktop 首次成功 Agent 任务

安装并启动 → 添加 Provider → 能力测试 → 进入 Agent → 选择工作区 → 选择权限预设 → Agent 读取并规划 → 用户审批写操作 → 执行 → 验证 → 展示结果与 Diff → 用户接受或回滚。

### 3.3 Skill 使用闭环

浏览 Skill → 查看能力和风险 → 启用 → 手动选择或自动匹配 → 显示激活原因 → 执行 → 查看 Skill 版本和效果 → 禁用、编辑、导出或卸载。

### 3.4 MCP 使用闭环

添加 Server → 配置安全凭据引用 → 测试连接 → 查看 tools/resources/prompts → 授权能力 → 启用 → 在任务中显示来源 → 调用与审计 → 重启、禁用或删除。

### 3.5 VS Code 使用闭环

安装 VSIX → 打开 Evir → 配置并测试 Provider → Ask 流式回答/停止 → 信任本地工作区 → Agent 数据去向披露 → 查看步骤与工具 → 审批写入/命令 → 验证 → Diff/回滚 → 新建会话或卸载。

当前实现已覆盖配置、Ask、停止、Workspace Trust、审批和最后写入回滚；Agent 步骤/工具结果/验证/完成摘要、High Contrast、完整本地化与公开安装升级仍未闭环。

### 3.6 CLI 使用闭环

安装 CLI → configure 隐藏输入凭据 → doctor → 参数/stdin Ask → 指定工作区 Agent → 数据去向披露 → 默认拒绝审批 → 验证/完成摘要 → Ctrl+C/错误恢复 → 升级或卸载。

当前实现已覆盖基础命令、真实流、工作区、审批和 SIGINT；友好配置向导、错误分类、中英文、JSON/JSONL、稳定退出码和 Agent 运行证据仍未闭环。

## 4. 产品验收门槛

一个功能只有同时具备以下状态才算产品闭环：

1. 入口明确。
2. 正常流程可完成。
3. 加载、空、错误、禁用和权限不足状态完整。
4. 失败后有下一步。
5. 数据保存和删除规则明确。
6. 可停止或取消。
7. 高风险行为可审批。
8. 有验证和结果反馈。
9. 多语言和多主题完整。
10. 性能不突破预算。

对 VS Code 与 CLI 还必须增加宿主验收：扩展真实安装/激活/主题/Workspace Trust；CLI 的 stdout/stderr/退出码/TTY/非 TTY/跨平台 Keyring。构建 VSIX 或 tarball 不是产品闭环证据。

## 5. 暂不纳入首发的内容

- Evir 云账号和云同步。
- Skill 商店和社区评分。
- 自动跨 Provider 路由和故障转移。
- 移动端完整 Agent。
- 多人协作空间。
- 无人值守高风险自动化。

这些能力不得以占位入口出现在首发 UI 中。

## 8. 个性化与设置闭环补充

- 个性化必须包含启用、编辑、预览、生效作用域、关闭、恢复和导出闭环。
- `SOUL.md` 只用于风格和原则，不得成为第二套可覆盖安全系统的“根提示词”。
- 通知必须包含开启、权限、触发条件、内容隐私、关闭和权限失效处理。
- Usage 必须区分准确、估算、不可用，并提供清空、导出和隐私会话策略。
- 快捷键必须可发现、可修改、冲突可解释、可恢复默认。
- 帮助必须支持首次配置闭环；反馈必须在无 Evir 后端的情况下完成。

## 9. V6 最终收口问题

### 9.1 “接入模型即可操作电脑”容易过度承诺

修正：产品承诺限定为“接入一个支持 Tool Calling 的模型即可开始 Desktop Agent”。普通聊天模型只启用 Ask。系统权限仍按需申请，但不要求用户提前理解和配置所有能力。

### 9.2 模型中途切换可能破坏 Tool 链和上下文

修正：引入 ModelSwitchCoordinator、能力/附件/上下文检查、跨 Provider 数据去向确认和结构化 Handoff。工具执行期间禁止静默切换。

### 9.3 上下文压缩可能误删关键约束

修正：用户约束、权限、任务状态、错误、变更和验证使用结构化状态单独保存；先归档工具噪声和可重读文件，再摘要旧对话。摘要版本化并可从本地原始数据重建。

### 9.4 全系统日志与隐私存在冲突

修正：Diagnostic/Audit/Crash 分离，统一脱敏、异步写入和空间预算；默认不记录正文。用户主动导出诊断包，不建立远程日志后门。Raw Protocol Capture 仅限时、明确授权。

### 9.5 Harness 可能导致控制流过度设计

修正：采用可拆卸 Middleware，每层有指标、测试和版本。无收益的启发式不得进入核心。仓库文档、AGENTS.md、测试和架构约束作为事实来源，自验证与循环检测成为必要基础设施。

### 9.6 高级功能可能破坏“小而美”

修正：已实现的 Skill、MCP 配置、个性化、Usage 和当前会话诊断统一进入设置；帮助、反馈、通知和命令面板尚未实现，不出现占位入口。主界面只保留模型、模式、输入、发送/停止和任务状态。
